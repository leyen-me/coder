# 数据存储对比：IndexedDB vs JSONL Transcript

## Coder 数据存储

### 技术选型
**IndexedDB**（通过 `idb` 库封装）

### 数据模型
```typescript
// src/lib/db/types.ts
type ChatSession = {
  id: string;
  title: string;
  createdAt: number;
  updatedAt: number;
  workspaceDir: string | null;
  model: string;
  sessionKind: SessionKind;
  autonomyMode: SessionAutonomyMode;
  // ...
}

type MessageRecord = {
  id: string;
  sessionId: string;
  role: 'user' | 'assistant' | 'system' | 'tool';
  content: string;
  messageKind: MessageKind;  // 'normal' | 'handoff' | 'handoff_continuation'
  // ...
}

type ToolRecord = {
  id: string;
  messageId: string;
  toolCallId: string;
  name: string;
  input: string;
  output: string;
  // ...
}
```

### 数据表
| 表名 | 内容 |
|------|------|
| sessions | 会话元数据 |
| messages | 消息记录 |
| tools | 工具调用记录 |
| skills | 用户技能 |
| automations | 自动化配置 |
| automationRuns | 自动化运行历史 |
| agentTodos | Agent 待办事项 |
| subscriptions | 订阅信息 |

### 特点
- **结构化查询**：支持索引、过滤、排序
- **浏览器原生**：无需外部数据库
- **容量限制**：受浏览器配额限制（通常几百 MB）
- **不可共享**：数据绑定到本地浏览器实例

## Claude Code 数据存储

### 技术选型
**JSONL Transcript**（磁盘文件）+ **Settings JSON**（配置）

### Transcript 格式
```
~/.claude/projects/<project-id>/transcripts/<session-id>.jsonl
```
每行一个 JSON 对象：
```json
{"type":"user","content":"帮我修复这个bug","timestamp":1234567890}
{"type":"assistant","tool_use":{"name":"Read","input":{"path":"src/foo.ts"}}}
{"type":"tool_result","result":{"content":"file content..."}}
{"type":"compact_boundary","compactMetadata":{"compactType":"auto",...}}
```

### 配置存储
```
~/.claude/settings.json          — 用户全局设置
.claude/settings.json            — 项目级设置
.claude/skills/                  — 项目级技能
.claude/hooks.json               — Hook 配置
```

### 特点
- **Git 可追踪**：项目级配置可提交到版本控制
- **可分享**：Settings 和 Skills 可通过 Git 分享给团队
- **无限容量**：受磁盘空间限制
- **`--resume` 恢复**：从 JSONL transcript 重建会话状态

## 对比分析

| 维度 | Coder (IndexedDB) | Claude Code (JSONL) |
|------|-------------------|---------------------|
| **查询能力** | ✅ 结构化查询、索引 | ❌ 线性扫描 |
| **容量** | 受限（几百 MB） | 无限（磁盘空间） |
| **可共享性** | ❌ 绑定本地浏览器 | ✅ Git 可追踪 |
| **恢复能力** | 依赖 DB 完整性 | ✅ --resume 从文件重建 |
| **团队协作** | ❌ 无法共享配置 | ✅ settings.json 可提交 |
| **调试便利** | 需要浏览器 DevTools | ✅ 直接查看文本文件 |
| **搜索性能** | ✅ 索引加速 | ❌ 全文扫描 |

## Coder 可学习的思想

### 1. 磁盘文件存储项目配置
Claude Code 的 `.claude/settings.json` 和 `.claude/skills/` 通过 Git 版本控制，实现团队共享。Coder 的配置存储在 IndexedDB，不可共享。

**建议**：Coder 可将项目级配置（Skills、Hooks、Settings）存储为磁盘文件（`.coder/` 目录），支持 Git 版本控制和团队共享。同时保留 IndexedDB 用于会话数据。

### 2. Transcript 持久化
Claude Code 的 JSONL transcript 记录了完整的对话历史，支持 `--resume` 恢复。Coder 的消息存储在 IndexedDB，无法在外部访问或恢复。

**建议**：Coder 可导出会话 transcript 为文件（JSONL 或 Markdown 格式），支持备份和分享。

### 3. 混合存储策略
理想的方案是混合使用两种存储：
- **IndexedDB**：会话消息、工具调用记录（需要快速查询和虚拟滚动）
- **磁盘文件**：项目配置、Skills、Hooks（需要版本控制和共享）

**建议**：Coder 当前架构已经是这种混合模式的前奏——将配置类数据迁移到磁盘文件，保留会话数据在 IndexedDB。

### 4. 会话导出功能
Claude Code 的 transcript 天然可分享。Coder 应提供会话导出功能（Markdown/JSONL），方便用户备份和分享对话历史。

**建议**：Coder 可增加 "导出会话" 功能，将完整对话（含工具调用）导出为可读格式。
