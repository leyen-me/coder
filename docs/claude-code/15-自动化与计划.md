# 自动化与计划对比：定时任务与工作流编排

## Coder 自动化系统

### 实现位置
`src/features/automations/` + `src/features/plan/`

### 自动化（Automations）
```typescript
type Automation = {
  id: string;
  name: string;
  description: string;
  prompt: string;       // 要执行的 AI 提示
  schedule: string;     // Cron 表达式
  workspaceDir: string;
  model: string;
  enabled: boolean;
  lastRunAt?: number;
  nextRunAt?: number;
}
```

- **调度器**：基于 `cron-parser` 解析 Cron 表达式
- **执行锁**：`automation-run-lock.ts` 防止并发执行
- **运行历史**：记录每次运行的状态和结果
- **UI**：Automations Page 提供卡片式管理界面

### 计划系统（Plan）
```typescript
type Plan = {
  id: string;
  sessionId: string;
  title: string;
  steps: PlanStep[];
  status: 'draft' | 'executing' | 'completed' | 'cancelled';
}

type PlanStep = {
  id: string;
  description: string;
  status: 'pending' | 'in_progress' | 'completed' | 'cancelled';
}
```

- **Plan 工具**：plan_create / plan_read / plan_update / plan_edit / plan_delete / plan_list
- **Plan Mode**：独立的规划 Agent 模式，只能使用只读工具 + plan_* + todo_write
- **执行流程**：规划 → 生成执行 Prompt → 切换到 Agent 模式执行

## Claude Code 计划与任务系统

### Plan Mode
```
EnterPlanModeTool.call() → 切换为只读权限模式
  → AI 探索代码库、分析需求、制定计划
ExitPlanModeV2Tool.call() → 恢复之前权限模式
  → AI 开始执行计划
```

### 任务系统 V2（Task Management）
```typescript
type Task = {
  id: string;
  title: string;
  status: 'pending' | 'in_progress' | 'completed' | 'failed';
  dependencies: string[];   // 依赖的其他任务 ID
  owner?: string;           // 认领的 Agent
  output?: string;          // 完成后的输出
}
```

- **TaskCreate/Update/List/Get/Output/Stop**：完整的 CRUD + 状态管理
- **依赖图**：任务间可声明依赖关系，依赖完成后自动解锁
- **竞争认领**：Swarm 模式下多个 Agent 竞争认领 pending 任务
- **文件锁**：`claimTask()` 原子操作保证只有一个 Agent 获得任务

### ScheduleCronTool
- AI 可直接创建定时任务
- 在 Agent 运行过程中动态调度后台任务

## 对比分析

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **自动化** | ✅ Cron 调度 + AI 执行 | ❌ 无独立自动化（ScheduleCronTool 有限） |
| **计划模式** | Plan Mode（只读 + plan_* 工具） | Plan Mode（Enter/Exit 工具切换权限） |
| **任务管理** | PlanSteps（描述性步骤列表） | Task System V2（状态机 + 依赖图 + 认领） |
| **Todo 系统** | todo_read / todo_write | TodoWriteTool |
| **任务依赖** | ❌ | ✅ 依赖图 + 自动解锁 |
| **竞争认领** | ❌ | ✅ Swarm 模式原子认领 |
| **AI 创建定时任务** | ❌（用户 UI 配置） | ✅ ScheduleCronTool |

## Coder 的优势

1. **完整的自动化系统**：Coder 的 Automations 功能支持 Cron 调度、执行锁、运行历史追踪，这是 Claude Code 缺少的
2. **UI 管理界面**：卡片式管理 + 运行历史查看，体验优于 CLI
3. **Plan CRUD 工具集**：6 个 Plan 工具提供完整的计划管理能力

## Coder 可学习的思想

### 1. 任务依赖图
Claude Code 的 Task System V2 支持任务间声明依赖关系。当依赖任务完成时，依赖它的任务自动解锁。这使得 Agent 可以编排有先后顺序的复杂工作流。

**建议**：Coder 的 Plan Step 可引入依赖关系——步骤 A 完成后自动解锁步骤 B/C/D。这比线性步骤列表更灵活。

### 2. Enter/Exit Plan Mode
Claude Code 通过工具调用动态切换权限模式（EnterPlanModeTool → 只读，ExitPlanModeTool → 恢复）。Coder 的 Plan Mode 是会话启动时固定的。

**建议**：Coder 可引入动态模式切换——Agent 在同一个会话中可以先进入 Plan Mode 探索，再切换到 Agent Mode 执行。

### 3. AI 创建定时任务
Claude Code 的 ScheduleCronTool 允许 AI 在运行过程中直接创建后台定时任务。Coder 的自动化需要用户通过 UI 配置。

**建议**：Coder 可引入 `create_automation` 工具，允许 Agent 动态创建定时任务。例如："每天凌晨运行测试并报告结果"。

### 4. 竞争认领机制
Swarm 模式的原子任务认领是并行执行的优雅方案。多个子 Agent 自主发现并认领待处理任务。

**建议**：Coder 的 Plan Step 可引入状态机和认领机制——多 Agent 场景下竞争执行不同步骤。

### 5. 自动化与计划的融合
Coder 有独立的 Automations 和 Plans 系统，两者没有关联。Claude Code 将任务管理整合到 Agent Loop 中。

**建议**：考虑将 Plan 和 Automation 融合——Automation 可以引用 Plan 作为执行模板，Plan 可以声明调度策略。
