# 工具系统对比：AI 的"双手"

## Coder 工具系统

### 架构设计
```
definitions.ts → AGENT_TOOL_DEFINITIONS (静态数组)
     ↓
registry.ts → TOOL_HANDLERS (名称→处理函数映射)
     ↓
executeToolCall() → JSON 解析 → handler(parsedArgs, context)
     ↓
ToolResultEnvelope { ok, tool, error | output }
```

### 工具列表（31个）
| 类别 | 工具 |
|------|------|
| **文件操作** | list_dir, read_file, write_file, replace_file, edit_file, get_workspace_tree |
| **搜索导航** | glob, grep |
| **Shell 执行** | shell, await, list_shells, kill_shell, read_shell_logs |
| **Web 能力** | web_search, browse_page |
| **技能系统** | list_skills, read_skill, create_skill, update_skill |
| **任务管理** | todo_read, todo_write |
| **计划管理** | plan_create, plan_read, plan_update, plan_edit, plan_delete, plan_list |
| **交互** | ask_question |
| **其他** | send_email |

### 工具定义方式
```typescript
export const READ_FILE_TOOL: AgentToolDefinition = {
  type: "function",
  function: {
    name: "read_file",
    description: "Read a text file with line numbers and pagination...",
    parameters: {
      type: "object",
      properties: { path, start_line, max_lines, respect_gitignore },
      required: ["path"],
      additionalProperties: false,
    },
  },
};
```

### 模式过滤
- **Agent Mode**：所有工具除了 ask_question、send_email、plan_*
- **Ask Mode**：只读工具（read_file、grep、glob、web_search 等）
- **Plan Mode**：只读工具 + plan_* + todo_write

## Claude Code 工具系统

### 架构设计
```
Tool<Input, Output, Progress> (结构化类型，35+字段)
     ↓
buildTool() 工厂函数 → 类型安全构造
     ↓
getAllBaseTools() → 50+ 基础工具列表
     ↓
getTools(permissionContext) → 权限过滤后传给 API
```

### 工具列表（60+个）
| 类别 | 工具 |
|------|------|
| **文件操作** | Read, Write, Edit, Glob, Grep, NotebookEdit |
| **命令执行** | Bash, PowerShell |
| **对话管理** | Agent, SendMessage, AskUserQuestion |
| **任务追踪** | TaskCreate/Update/List/Get/Output/Stop |
| **Web 能力** | WebFetch, WebSearch, WebBrowser |
| **规划模式** | EnterPlanMode, ExitPlanMode, ToolSearch |
| **MCP** | MCPTool, ListMcpResources, ReadMcpResource, McpAuth |
| **技能** | SkillTool, DiscoverSkillsTool |
| **工作树** | EnterWorktree, ExitWorktree |
| **其他** | BriefTool, ConfigTool, ScheduleCron, Sleep, Snip, TerminalCapture, ... |

### 工具接口（35+ 字段）
```typescript
type Tool<Input, Output, Progress> = {
  // 核心四要素
  name: string
  description(input): Promise<string>    // 动态描述
  inputSchema: z.ZodType                 // Zod schema
  call(args, context, canUseTool, parentMessage, onProgress): Promise<ToolResult>
  
  // 注册与发现
  aliases?: string[]
  searchHint?: string                    // ToolSearch 关键词
  shouldDefer?: boolean                  // 延迟加载
  alwaysLoad?: boolean                   // 永不延迟
  isEnabled(): boolean                   // 运行时开关
  
  // 安全与权限
  validateInput?(input, context): Promise<ValidationResult>
  checkPermissions(input, context): Promise<PermissionResult>
  isReadOnly(input): boolean
  isDestructive?(input): boolean
  isConcurrencySafe(input): boolean
  interruptBehavior?(): 'cancel' | 'block'
  
  // 输出与渲染
  maxResultSizeChars: number             // 结果字符上限
  renderToolResultMessage?: React.FC     // UI 渲染组件
  renderToolUseMessage?: React.FC
  
  // 上下文
  prompt?(): string                      // System Prompt 注入
  getPath?(input): string | null         // 提取文件路径
}
```

### 工具调用链路
```
API 返回 tool_use → StreamingToolExecutor.addTool()
  → findToolByName() → validateInput() → canUseTool() (UI确认)
  → checkPermissions() → call() → ToolResult
  → mapToolResultToToolResultBlockParam() → 追加到对话
```

## 对比分析

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **工具定义** | JSON Schema（OpenAI format） | Zod Schema + 结构化类型 |
| **注册方式** | 静态数组 + 运行时过滤 | 动态组装（每次 API 调用时构建） |
| **工具数量** | 31 个 | 60+ 个 |
| **权限检查** | 模式级过滤（agent/ask/plan） | validateInput + checkPermissions 双重检查 |
| **并行执行** | 不支持 | StreamingToolExecutor 支持 |
| **输出控制** | 无限制 | maxResultSizeChars + 持久化到磁盘 |
| **UI 渲染** | 独立组件（tool-display） | 每个工具自带 render 方法 |
| **进度反馈** | 通过 onEvent 回调 | onProgress 回调 + ToolProgress 类型 |
| **工具搜索** | 无 | ToolSearch（延迟加载+关键词发现） |
| **MCP 支持** | 无 | 完整 MCP 协议支持 |

## Coder 可学习的思想

### 1. 工具即结构化类型
Claude Code 的 `Tool<Input, Output, Progress>` 是一个包含 35+ 字段的结构化类型，每个字段有明确语义。Coder 的工具定义只有 JSON Schema + handler 函数，缺少声明式元数据。

**建议**：引入类似的结构化工具类型，将权限属性（isReadOnly、isDestructive）、输出限制（maxResultSizeChars）、并发安全（isConcurrencySafe）等作为工具的声明式属性。

### 2. 动态工具组装
Claude Code 在每次 API 调用时通过 `getTools()` 重新构建工具列表，考虑运行时状态（feature flags、权限规则、MCP 连接）。Coder 的 `getAgentToolDefinitions()` 仅做静态过滤。

**建议**：引入动态工具注册机制，支持根据运行时条件（如 MCP 服务器连接状态、workspace 类型）调整可用工具集。

### 3. 工具结果预算控制
Claude Code 的 `maxResultSizeChars` + `applyToolResultBudget()` 机制防止大输出浪费上下文空间。Coder 的工具结果直接序列化回传，无截断。

**建议**：为每个工具定义 `maxResultSizeChars`，超出时截断并提示 AI 使用分页参数重新读取。

### 4. 并行工具执行
Claude Code 的 `StreamingToolExecutor` 在流式过程中就开始执行已确定的工具调用。Coder 串行执行所有工具。

**建议**：对于独立性工具（read_file、glob、grep 等），支持并行执行以加速多工具调用的场景。

### 5. 进度反馈系统
Claude Code 的 `ToolCallProgress<P extends ToolProgressData>` 允许工具在执行过程中推送进度更新，UI 实时显示。Coder 只有 started/finished 两个事件点。

**建议**：引入细粒度进度回调，让长时间运行的工具（shell、web_search）能推送执行进度。

### 6. 工具搜索与延迟加载
Claude Code 的 ToolSearch 允许 AI 通过关键词发现工具，配合 `shouldDefer` 实现按需加载。这减少了 System Prompt 中的工具描述体积。

**建议**：对于工具数量增长后的 Coder，可引入类似的延迟加载机制，减少每次 API 调用的工具描述开销。

### 7. MCP 协议支持
Claude Code 原生支持 MCP（Model Context Protocol），可以连接外部工具服务器。Coder 完全缺少此能力。

**建议**：考虑引入 MCP 客户端支持，允许用户连接外部工具服务器扩展 Agent 能力。

### 8. 中断行为控制
Claude Code 的 `interruptBehavior()` 定义用户中断时的行为（cancel vs block）。Coder 通过 AbortSignal 统一取消所有进行中的操作。

**建议**：为每个工具声明中断行为，允许部分工具（如 read_file）可安全取消，部分工具（如 shell 执行）必须等待完成。
