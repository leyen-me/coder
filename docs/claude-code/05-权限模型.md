# 权限模型对比：安全边界设计

## Coder 权限模型

### 实现方式
基于 `AgentMode` 的简单工具过滤：

```typescript
// registry.ts - getAgentToolDefinitions(mode)
if (mode === "ask") {
  // 只读工具白名单
  return AGENT_TOOL_DEFINITIONS.filter(tool => ASK_MODE_TOOL_NAMES_SET.has(tool.name));
}
if (mode === "plan") {
  // 只读工具 + plan_* + todo_write
  return AGENT_TOOL_DEFINITIONS.filter(tool => PLAN_MODE_TOOL_NAMES_SET.has(tool.name));
}
// agent mode - 排除 ask_question, send_email, plan_*
return AGENT_TOOL_DEFINITIONS.filter(tool => !AGENT_MODE_EXCLUDED_SET.has(tool.name));
```

### 执行时权限检查
```typescript
// executeToolCall() - 执行时的二次校验
if (!isToolAllowedInMode(name, context.agentMode)) {
  return { ok: false, error: { code: "tool_not_allowed_in_mode" } };
}
```

### 三模式
| 模式 | 可用工具 | 适用场景 |
|------|---------|---------|
| **agent** | 所有工具（除 ask_question、send_email、plan_*） | 正常编码任务 |
| **ask** | 只读工具（read_file、grep、glob、web_search 等） | 问答查询 |
| **plan** | 只读工具 + plan_* + todo_write | 规划阶段 |

## Claude Code 权限模型

### 三级权限行为
每次工具调用经过 `canUseTool()` → `checkPermissions()` 双重检查，返回三种裁决之一：

| 行为 | 含义 | 典型场景 |
|------|------|---------|
| **Allow** | 自动放行，用户无感知 | Read 读取项目内文件 |
| **Ask** | 弹出确认对话框 | Bash 执行未知命令 |
| **Deny** | 直接拒绝 | 尝试执行被禁止的命令 |

### 五层规则来源（优先级从高到低）
```
1. session     — 用户当前对话手动授权（"Always allow"）
2. cliArg      — 命令行 --allow/--deny 参数
3. command     — Skill 工具的 allowedTools 白名单
4. projectSettings — .claude/settings.json（团队共享）
5. userSettings — ~/.claude/settings.json（跨项目）
6. policySettings — 企业管理员策略（不可覆盖）
```

### 三维度匹配引擎
1. **工具名匹配**：精确匹配工具名或 MCP server 级别通配
2. **命令模式匹配**：Bash 命令 AST 解析（tree-sitter），提取子命令匹配
3. **路径匹配**：文件工具通过 `getPath()` 提取路径，与 glob 模式匹配

### Denial Tracking（死循环防护）
```typescript
const DENIAL_LIMITS = {
  maxDenialsPerTool: 3,        // 同一工具连续拒绝上限
  cooldownPeriodMs: 30_000,    // 冷却期 30 秒
}
```
当 AI 被连续拒绝达到上限时，系统注入消息强制 AI 改变策略。

### 权限模式
| 模式 | 值 | 行为 |
|------|-----|------|
| **Default** | `'default'` | 敏感操作逐一确认 |
| **Plan** | `'plan'` | 只能读不能写 |
| **Auto** | `'auto'` | transcript classifier 自动决策 |
| **Bypass** | `'bypassPermissions'` | 完全信任（需显式参数） |

## 对比分析

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **权限粒度** | 模式级（3种） | 规则级（五层来源 × 三维度匹配） |
| **规则来源** | 无外部配置 | session/cli/project/user/policy 五层 |
| **匹配维度** | 仅工具名 | 工具名 + 命令模式 + 文件路径 |
| **动态更新** | 不支持运行时修改 | 用户可 "Always allow" 持久化规则 |
| **死循环防护** | ToolCallStallDetector（检测重复调用） | Denial Tracking（检测连续拒绝） |
| **权限 UI** | 无交互确认 | Ask 模式弹确认对话框 + 建议规则 |
| **Bash 命令分析** | 无 | tree-sitter AST 解析判断只读性 |
| **Skill 白名单** | 无 | allowedTools 精确控制 Skill 可用工具 |

## Coder 可学习的思想

### 1. 细粒度权限规则系统
Claude Code 的三维度匹配（工具名/命令/路径）允许用户精确控制 AI 的行为边界。例如：
- `"Bash(git commit*)"` → Allow（允许 git commit）
- `"Edit(src/**)"` → Allow（允许编辑 src 目录）
- `"Bash(rm -rf*)"` → Deny（禁止危险删除）

**建议**：Coder 可引入基于规则的权限系统，支持用户通过配置文件定义 allow/deny/ask 规则。即使是简单的 JSON 配置也能大幅提升安全性。

### 2. 多层规则来源
五层规则来源允许不同粒度的控制——项目级共享规则、用户级个人偏好、会话级临时授权。

**建议**：Coder 可引入项目级 `.coder/settings.json` + 全局 `~/.coder/settings.json` 双层配置，支持团队协作时的统一策略。

### 3. Denial Tracking 死循环防护
当 AI 反复请求被拒绝的操作时，Denial Tracking 强制其改变策略。这比 Coder 的 ToolCallStallDetector（检测重复工具调用）更精准——它检测的是"连续被拒"而非"重复调用"。

**建议**：Coder 可在权限拒绝后记录拒绝计数，达到阈值后注入系统消息引导 AI 换策略。

### 4. Bash 命令只读分析
Claude Code 使用 tree-sitter 对 Bash 命令做 AST 解析，自动判断 `git status` 是只读的（Allow），`git push` 是写操作（Ask）。

**建议**：Coder 的 Shell 工具可引入常见的只读命令白名单（ls、cat、grep、git status 等），实现基础的自动放行。

### 5. 运行时权限修改
Claude Code 允许用户在 Ask 对话框中选择 "Always allow"，规则被持久化到 settings 文件并立即生效。

**建议**：Coder 可在 ask_question 工具的确认界面中提供 "记住此选择" 选项，将规则保存到设置中。

### 6. Plan Mode 权限隔离
Claude Code 的 Plan Mode 通过 `prepareContextForPlanMode()` 切换为只读模式，退出时自动恢复之前的模式。Coder 的 plan mode 仅是工具过滤，不改变权限上下文。

**建议**：Coder 可引入更结构化的权限上下文对象（类似 ToolPermissionContext），支持模式的平滑切换和恢复。

### 7. Skill 工具白名单
Claude Code 的 Skill 通过 `allowedTools` frontmatter 声明可用工具，执行时注入到权限上下文的 `alwaysAllowRules.command`。

**建议**：Coder 的 Skill 系统可引入类似的 `allowed-tools` frontmatter，精确控制每个 Skill 的工具权限范围。
