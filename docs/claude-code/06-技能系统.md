# 技能系统对比：Prompt 即能力

## Coder 技能系统

### 实现位置
`src/features/skills/` + `src/features/agent/tools/{list-skills,read-skill,create-skill,update-skill}.ts`

### 架构设计
```
DB (IndexedDB skills table)
  ↓
registry.ts → getSystemSkills() + getUserSkills(sessionId)
  ↓
resolve-skills.ts → 解析用户消息中的 /skill-name 引用
  ↓
system-prompt → 将启用技能的描述注入 System Prompt
```

### Skill 结构
```typescript
type Skill = {
  slug: string;           // 唯一标识（小写字母、数字、连字符）
  name: string;           // 显示名称
  description: string;    // 何时使用此技能
  content: string;        // Markdown 格式的技能指令
  enabled: boolean;       // 是否启用
  source: 'system' | 'user';
  sessionId?: string;     // 用户技能绑定到会话
}
```

### Skill 执行流程
1. 用户输入 `/skill-name` 或在消息中引用技能
2. `parseSkillReferences()` 解析引用
3. 查找对应 Skill 的 `content`（完整 Markdown 指令）
4. 将 content 注入为 UserMessage，AI 按指令执行

### 管理方式
- **系统技能**：硬编码在 `src/features/skills/system/registry.ts`
- **用户技能**：通过 `create_skill` / `update_skill` 工具创建，存储在 IndexedDB
- **UI 管理**：Skills Page 提供卡片式管理界面

### Frontmatter
Coder 的 Skill **不支持 YAML frontmatter**。所有配置通过结构化字段（slug、name、description、content）管理。

## Claude Code 技能系统

### 实现位置
`src/skills/` + `src/tools/SkillTool/` + `src/commands.ts`

### 架构设计
```
磁盘 SKILL.md → parseFrontmatter() → parseSkillFrontmatterFields() (17个字段)
  ↓
createSkillCommand() → Command 对象
  ↓
getSkillDirCommands() memoize 缓存
  ↓
formatCommandsWithinBudget() → 截断后注入 System Prompt
  ↓
SkillTool.call() → inline 或 fork 执行
```

### Skill 的五个来源
1. **内置命令**：硬编码在 `src/commands.ts`（70+ 条，TypeScript 模块）
2. **Bundled Skills**：编译时打包，延迟文件提取，符号链接安全防护
3. **磁盘 Skills**：`.claude/skills/skill-name/SKILL.md`（项目级/用户级/管理级）
4. **MCP Skills**：MCP Server prompt 动态转换为 Command
5. **Legacy Commands**：`/commands/` 目录（向后兼容）

### Frontmatter（17 个字段）
```yaml
---
name: code-review
description: 系统性代码审查
when_to_use: "用户说审查代码、找 bug"
allowed-tools: [Read, Grep, Glob]
argument-hint: "<file-or-directory>"
arguments: [path]
model: opus
effort: high
context: fork                    # inline（默认）| fork
agent: code-reviewer
user-invocable: true
disable-model-invocation: false
version: "1.0"
paths: ["src/**/*.ts"]          # 条件激活路径
hooks:                           # Hook 配置
  PreToolUse: [...]
shell: ["bash"]
---
```

### 两条执行路径
| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **Inline**（默认） | Skill Prompt 注入为 UserMessage，在主对话中执行 | 轻量级技能 |
| **Fork** | 在独立子 Agent 中执行，拥有隔离上下文 | 长时间运行的复杂任务 |

### 动态发现与条件激活
- **基于文件路径的动态发现**：操作文件时向上遍历查找 `.claude/skills/`
- **条件激活**（paths frontmatter）：只有当被操作文件匹配 paths 模式时才激活 Skill
- **使用频率排名**：指数衰减算法（7天半衰期，0.1保底权重）

### Prompt 预算控制
Skill 列表注入 System Prompt 时有严格字符预算：
- 预算 = `contextWindowTokens × 4 chars/token × 1%`（约 8000 字符）
- 单条上限 250 字符
- Bundled Skills 不可截断
- 三级降级策略：完整描述 → 均分预算 → 仅名称

## 对比分析

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **存储方式** | IndexedDB（结构化数据） | 磁盘文件（SKILL.md + frontmatter） |
| **Frontmatter** | 无（纯结构化字段） | 17 个 YAML frontmatter 字段 |
| **执行模式** | 仅 Inline（注入为消息） | Inline + Fork（子 Agent 隔离执行） |
| **工具白名单** | 无 | allowedTools 精确控制 |
| **模型覆盖** | 无 | model frontmatter 可指定不同模型 |
| **条件激活** | 无 | paths 模式匹配文件路径自动激活 |
| **动态发现** | 无 | 基于文件操作的向上遍历发现 |
| **使用频率排名** | 无 | 指数衰减算法（7天半衰期） |
| **Prompt 预算** | 无限制注入 | 1% 上下文窗口预算 + 三级降级 |
| **Skill 来源** | 系统内置 + 用户创建 | 5 种来源（内置/打包/磁盘/MCP/遗留） |
| **符号链接安全** | 无 | O_NOFOLLOW \| O_EXCL 防止链接攻击 |

## Coder 可学习的思想

### 1. Frontmatter 声明式配置
Claude Code 的 17 个 frontmatter 字段允许 Skill 声明：工具白名单、模型覆盖、努力级别、执行模式、条件激活路径等。这是一个强大的**声明式工作流引擎**。

**建议**：Coder 的 Skill 可引入可选的 YAML frontmatter，支持 `allowed-tools`、`when-to-use` 等关键字段。保持向后兼容（无 frontmatter 时行为不变）。

### 2. Fork 执行模式
长时间运行的复杂 Skill（如全面代码审查）在主对话中执行会污染上下文。Fork 模式在独立子 Agent 中执行，结果提取后释放全部消息。

**建议**：Coder 可引入 Skill 的 Fork 执行模式——启动独立的 Agent Loop 实例，完成后将结果摘要回传到主会话。

### 3. 条件激活（paths）
当 AI 操作匹配 `paths` 模式的文件时自动激活相关 Skill。例如编辑 `*.test.ts` 时自动激活测试编写 Skill。这是**上下文感知的能力发现**。

**建议**：Coder 可在工具执行时检测操作路径，自动注入匹配的 Skill 指令到当前 Turn。

### 4. Prompt 预算控制
Skill 描述注入 System Prompt 时有严格的字符预算和三级降级策略。这防止大量 Skill 占满上下文空间。

**建议**：Coder 在注入 Skill 描述到 System Prompt 时应计算总 token 开销，超过阈值时截断或省略低优先级 Skill。

### 5. 使用频率排名
指数衰减的使用频率排名让常用 Skill 在 Prompt 中优先级更高（预算不足时优先保留）。

**建议**：Coder 可记录 Skill 使用次数和时间，在 System Prompt 注入时按排名排序。

### 6. 磁盘文件 vs IndexedDB
Claude Code 使用磁盘 SKILL.md（Git 可追踪、可分享），Coder 使用 IndexedDB（会话绑定、不可分享）。

**建议**：Coder 可考虑支持磁盘存储的 Skill（如 `.coder/skills/` 目录），便于版本控制和团队共享。同时保留 IndexedDB 作为会话级临时 Skill 的存储。

### 7. MCP Skills
Claude Code 将 MCP Server 的 prompt 动态转换为 Skill Command，支持远程技能加载。

**建议**：Coder 未来若引入 MCP 支持，可将 MCP prompts 自动映射为可用 Skill。

### 8. 符号链接安全防护
Bundled Skill 的文件提取使用 `O_NOFOLLOW | O_EXCL` 防止符号链接攻击。这是容易被忽略的安全细节。

**建议**：Coder 在处理用户技能文件路径时应做规范化检查，防止路径遍历攻击。
