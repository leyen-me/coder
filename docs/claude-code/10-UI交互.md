# UI 与交互对比：桌面应用 vs 终端 TUI

## Coder UI 系统

### 架构设计
```
Tauri 桌面窗口
  ├── 侧边栏（导航）
  │     ├── 会话列表
  │     ├── 历史页面入口
  │     ├── 设置入口
  │     ├── 技能管理入口
  │     └── 自动化入口
  ├── 主列（聊天区域）
  │     ├── 消息列表（虚拟滚动）
  │     ├── 工具调用展示
  │     ├── Prompt Composer（TipTap 富文本输入）
  │     └── @提及弹出（文件/技能引用）
  ├── 右面板
  │     ├── 文件树
  │     ├── 文件预览/编辑器（Monaco）
  │     └── 计划预览
  └── 底部面板
        ├── xterm.js 终端
        └── 进程日志查看器
```

### UI 技术栈
- **框架**：React 19 + React Router 7
- **组件库**：shadcn/ui (Radix UI) + Base UI
- **样式**：Tailwind CSS 4
- **富文本**：TipTap（Prompt Composer）
- **终端**：xterm.js + @xterm/addon-fit
- **代码编辑**：@monaco-editor/react
- **动画**：Motion (Framer Motion)
- **虚拟滚动**：@tanstack/react-virtual
- **主题**：next-themes（亮/暗模式）

### 交互特性
- **@提及**：在输入框中 @文件路径 / @技能名，自动插入引用节点
- **拖放**：支持外部文件拖入、工作区路径拖放
- **键盘快捷键**：可自定义的全局快捷键系统
- **多面板布局**：React Resizable Panels 支持调整面板大小
- **搜索**：全局搜索对话框（cmdk）

## Claude Code UI 系统

### 架构设计
```
终端 TUI (Ink React)
  ├── 顶部状态栏
  │     ├── 模型名称
  │     ├── Token 用量 / 成本
  │     └── 活动描述（"Reading src/foo.ts"）
  ├── 消息区域
  │     ├── 用户消息
  │     ├── AI 回答（流式逐字显示）
  │     └── 工具调用展示（各工具自定义渲染组件）
  ├── 工具结果展示
  │     ├── FileEdit → 语法高亮 diff
  │     ├── Bash → 实时输出 + 进度指示
  │     ├── Grep → 高亮匹配 + 文件路径链接
  │     └── Agent → 子 Agent 进度条
  └── PromptInput（底部输入行）
        ├── /命令系统
        ├── 文件附件
        └── 图片支持
```

### UI 技术栈
- **框架**：React (Ink) — 终端 React 渲染引擎
- **组件**：自定义设计系统（无第三方 UI 库）
- **样式**：chalk / ansi 颜色码
- **动画**：自定义 spinner + 进度条
- **输入**：ink-text-input / ink-select

### 交互特性
- **/命令系统**：70+ 斜杠命令（/compact、/review、/permissions 等）
- **权限对话框**：Ask 模式下弹确认对话框（允许/拒绝/始终允许）
- **Vim 模式**：输入行支持 Vim 键位
- **语音输入**：音频捕获 + 语音转文字
- **Buddy**：终端精灵动画（执行状态可视化）

## 对比分析

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **UI 范式** | 图形桌面应用（多面板） | 终端 TUI（单面板流式） |
| **空间利用** | 多面板并行展示（聊天+文件树+终端） | 线性滚动（消息+工具结果混排） |
| **文件浏览** | 右面板文件树 + Monaco 编辑器 | 无独立文件浏览器（依赖工具调用） |
| **输入体验** | TipTap 富文本 + @提及 + 拖放 | /命令 + 纯文本输入行 |
| **工具展示** | 独立 tool-display 组件 | 每个工具自带 render 方法 |
| **权限交互** | ask_question 工具卡片 | 终端确认对话框（始终允许选项） |
| **主题支持** | next-themes 亮暗切换 | chalk 颜色码 + theme 配置 |
| **快捷键** | 可自定义全局快捷键系统 | Vim 模式 + 固定快捷键 |
| **扩展性** | React 组件体系易于扩展 | 终端渲染能力受限 |

## Coder 已有的优势

1. **多面板布局**：同时查看聊天、文件树、代码编辑器、终端，信息密度高
2. **富文本输入**：TipTap 支持格式化、@提及、图片附件、技能引用
3. **文件编辑**：Monaco 编辑器提供完整的代码编辑体验（语法高亮、自动补全）
4. **拖放支持**：外部文件拖入、工作区路径拖放
5. **可自定义快捷键**：灵活的键盘快捷键系统
6. **桌面原生集成**：Tauri 提供的文件系统访问、通知、窗口管理

## Claude Code 的优势

1. **工具渲染多样性**：每个工具自带 React 渲染组件，展示形式丰富（diff 视图、进度条、折叠模式）
2. **/命令系统**：70+ 斜杠命令提供快速操作入口
3. **权限对话框**：优雅的终端确认 UI，支持 "始终允许" 规则持久化
4. **实时进度推送**：onProgress 回调驱动的实时更新
5. **活动描述**：Spinner 显示具体活动（"Reading src/foo.ts"）而非通用加载动画

## Coder 可改进的方向

### 1. 工具结果渲染多样化
Claude Code 每个工具自带 `renderToolResultMessage()` 和 `renderToolUseMessage()`，根据不同工具定制展示。Coder 的工具展示相对统一。

**建议**：Coder 可为不同工具类型（文件 diff、shell 输出、搜索结果）设计差异化展示组件，增强可读性。

### 2. 活动状态描述
Claude Code 的 `getActivityDescription()` 为 spinner 提供具体活动描述。Coder 的加载状态较为通用。

**建议**：Coder 在工具执行时显示具体活动描述（如 "正在读取 src/foo.ts"、"正在执行 npm test"）。

### 3. /命令系统
Claude Code 的 70+ 斜杠命令提供快速操作入口。Coder 目前没有类似机制。

**建议**：Coder 可在 Prompt Composer 中引入 `/` 命令系统，支持 `/compact`、`/review`、`/permissions` 等快捷操作。

### 4. 权限确认 UI
Claude Code 的 Ask 对话框提供 "允许" / "拒绝" / "始终允许" 三个选项，并将规则持久化。Coder 的 ask_question 工具是通用的问答卡片。

**建议**：Coder 可引入专用的权限确认组件，支持规则持久化和快速决策。

### 5. 工具进度实时更新
Claude Code 的 onProgress 回调在工具执行过程中实时推送进度到 UI。Coder 只有 started/finished 两个事件点。

**建议**：Coder 的工具执行可通过事件流推送中间状态（如 shell 命令的实时输出、web_search 的搜索进度）。
