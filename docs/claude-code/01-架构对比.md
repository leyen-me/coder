# 架构对比：Coder vs Claude Code

## 概述

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **运行环境** | Tauri 桌面应用（Electron 替代方案） | Node.js CLI（终端 TUI） |
| **UI 框架** | React 19 + React Router + shadcn/ui | React (Ink) + 终端渲染 |
| **构建工具** | Vite + TypeScript | tsx / esbuild |
| **通信协议** | OpenAI 兼容 API（流式） | Anthropic Messages API（Beta Raw Stream） |
| **数据存储** | IndexedDB（浏览器本地存储） | JSONL Transcript（磁盘文件） |
| **架构风格** | SPA 单页应用，前端主导 | CLI TUI，后端逻辑主导 |
| **多提供商** | 原生支持任意 OpenAI 兼容 API | 默认 Anthropic，支持 Bedrock/Vertex/Azure |

## Coder 架构特点

```
┌─────────────────────────────────────┐
│           Tauri 桌面窗口              │
│  ┌──────────┬──────────┬──────────┐ │
│  │ 侧边栏   │  主列    │  右面板  │ │
│  │ (导航)   │ (聊天)   │(文件树)  │ │
│  └──────────┴──────────┴──────────┘ │
│  ┌─────────────────────────────────┐ │
│  │       底部面板 (终端)            │ │
│  └─────────────────────────────────┘ │
└─────────────────────────────────────┘
         ↓
   Agent Loop (纯 TS 逻辑)
         ↓
   OpenAI 兼容 API
```

- **前端驱动**：所有 UI 状态通过 React Context + Zustand 管理
- **路由系统**：React Router 7，支持多页面导航（聊天、历史、设置、技能、自动化）
- **数据库**：IndexedDB 持久化会话、消息、工具调用记录
- **原生能力**：通过 Tauri 插件访问文件系统、Shell 执行

## Claude Code 架构特点（五层架构）

```
┌──────────────────────┐
│   交互层 (REPL/TUI)   │ ← Ink React 终端 UI
├──────────────────────┤
│   编排层 (QueryEngine)│ ← 会话状态、成本追踪、Transcript
├──────────────────────┤
│  核心循环层 (query.ts) │ ← Agentic Loop 状态机
├──────────────────────┤
│   工具层 (50+ Tools)  │ ← Tool 接口 + MCP 扩展
├──────────────────────┤
│   通信层 (API Client) │ ← Anthropic API Streaming
└──────────────────────┘
```

- **五层分层**：交互层 → 编排层 → 核心循环层 → 工具层 → 通信层
- **AsyncGenerator**：`query()` 是异步生成器，通过 `yield` 产出事件
- **Transcript 持久化**：JSONL 格式记录完整对话，支持 `--resume` 恢复
- **Bridge 模式**：支持远程执行（代码运行在远端服务器，UI 在本地）

## 相同点

1. **Agent Loop 核心**：两者都有 `while(true)` 循环，AI 思考 → 工具调用 → 结果回传
2. **工具系统**：都提供文件读写、Shell 执行、Web 搜索、技能系统等工具
3. **流式通信**：API 请求均为流式传输，支持实时 UI 更新
4. **上下文管理**：都有 token 预算估算和上下文压缩/交接机制
5. **事件驱动**：通过事件回调驱动 UI 更新

## 不同点

| 维度 | Coder | Claude Code |
|------|-------|-------------|
| **UI 范式** | 图形桌面应用（多面板布局） | 终端 TUI（单面板流式输出） |
| **工具定义** | JSON Schema + OpenAI function calling | Zod Schema + Anthropic tool_use |
| **工具注册** | 静态数组 `AGENT_TOOL_DEFINITIONS` | 动态组装 `getTools()`（每次 API 调用时重新构建） |
| **权限模型** | 基于 AgentMode 的简单过滤（agent/ask/plan） | 三级权限体系（Allow/Ask/Deny）+ 五层规则来源 |
| **上下文压缩** | Handoff（交接到新会话） | 三层压缩策略（MicroCompact / Session Memory / API 摘要） |
| **子 Agent** | 无原生子 Agent 支持 | Coordinator Mode + Agent Swarms |
| **扩展性** | Skills（Prompt 即能力） | Skills + Hooks + Plugins + MCP |
| **错误恢复** | Chat Retry（流空闲恢复 + 通用重试） | 4 种恢复路径 + 模型降级 + Prompt-Too-Long 紧急降级 |

## Coder 可从 Claude Code 学习的思想

### 1. 动态工具组装
Claude Code 在每次 API 调用时重新构建工具列表（`getTools()`），因为 `isEnabled()` 可能随运行时状态变化。Coder 目前是静态数组过滤，可考虑引入动态过滤机制。

### 2. 三层上下文压缩
Claude Code 的 MicroCompact → Session Memory → API 摘要三级压缩策略非常精细。Coder 目前只有 Handoff（交接），可引入局部压缩减少交接频率。

### 3. 权限模型深化
Claude Code 的五层规则来源 + 三维度匹配（工具名/命令/路径）+ Denial Tracking 死循环防护是一套完整的权限体系。Coder 的 AgentMode 过滤过于简单。

### 4. 工具结果预算控制
Claude Code 通过 `maxResultSizeChars` 控制输出大小，超出则持久化到磁盘。Coder 的工具结果直接返回，可能浪费上下文空间。

### 5. Hook 生命周期系统
22 种 Hook 事件 + 6 种 Hook 类型 + JSON Schema 输出协议构成强大的扩展机制。Coder 完全缺少此能力。

### 6. 工具并行执行
Claude Code 的 `StreamingToolExecutor` 在流式过程中就开始并行执行工具，不等流结束。Coder 是串行的（先完成流 → 再执行工具）。

### 7. 错误恢复策略
Claude Code 有 4 种继续条件（正常循环、max_output_tokens 恢复、PTL 恢复、Stop Hook 阻塞重试）和模型降级机制。Coder 仅有简单的 chat retry。

### 8. 子 Agent 编排
Coordinator Mode + Agent Swarms 支持多 Agent 协作。这是 Coder 完全缺失的能力。
